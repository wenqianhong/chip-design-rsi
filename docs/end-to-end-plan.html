完整链路首道任务如何串联最终评分交付顺序

01 · 真正贯通的是产物和约束

① 目标与设计规格功能、接口、负载、时钟、工艺
→
② 微架构选择受支持的设计配置 / 结构修改
→
③ RTL 实现原版或模型提交的冻结硬件代码
↓
④ 功能验证现成测试、签名、适用的形式化检查
→
⑤ 综合同一 RTL → 工艺映射网表
→
⑥ 物理实现该网表 → 布局 / 时钟树 / 布线
↓

⑦ 实现后的检查与报告

用该布局的网表、寄生参数及固定约束分析时序；在平台提供规则时检查 DRC / LVS。输出每项检查范围、状态、证据与限制。研究环境的检查完成不等于获得晶圆厂正式签核。

最重要的连接点：ChampSim 的预取器 C++ 不会自动变成可综合 RTL，PicoRV32 也不能拿来承接这个预取器的硬件实现。现有 ChampSim 保留为独立任务类型。若要把架构仿真纳入同一道完整任务，必须给同一 CPU 建立参数到 RTL 的映射，固定 workload 和内存模型，并与 RTL 的周期 / 事件统计校准；否则架构预测只作辅助，不作为最终硬件成绩。

02 · 首道完整任务：优化一个小型 CPU

PicoRV32 为候选；基线跑通后锁定
输入

原版 + 固定条件

CPU RTL、接口与指令集约束、程序镜像、测试、工艺平台、时钟与 I/O 约束、允许修改清单、资源预算。明确核心边界：首任务评估 CPU 核心，测试内存不计入核心面积。

模型提交

一次性代码修改

只改清单允许的 CPU 内部 RTL，保持接口与功能。不能改固件、测试、计数器所在的独立 testbench、工艺库或评分约束。基线硬件配置固定，允许修改的结构在任务中写明。

环境返回

从功能到实现的结果

编译 / 测试结果、程序周期、网表、布局图、时序、面积、规则检查，以及原始日志和版本。阶段失败也产出报告，下游明确标记未运行。

任务示例：“保持这个 CPU 的指令行为与外部接口不变，优化给定内部逻辑；在固定程序上减少执行周期，同时满足目标时钟和预设面积上限。”目标、测试与上限必须在模型提交前冻结。

首任务用上游指令测试检查功能、用上游 Dhrystone 执行程序。一个程序只代表一个测量范围；完成首道贯通任务后再扩充固定任务集。规格 / 微架构阶段先表达为明确约束和受支持的结构选择，不虚构自动架构设计或 C++ 到 RTL 翻译能力。

阶段状态机

queued → running → passed / failed / timeout / blocked / unsupported

依赖未通过的下游标记 skipped，并指向原因。形式化无法证明与发现反例分开记录；未经运行的工具不能标成功。

统一版本与缓存

每步记录输入和输出 hash、工具及工艺版本、参数、约束、随机种子和耗时。缓存键覆盖所有依赖，RTL 或工艺变化就使对应下游缓存失效。

恢复任务只能重跑相同冻结产物，不能趁失败改变候选或放松约束。

04 · 一个任务，多项可核对的成绩

第一关：功能正确

所有规定功能项通过，检查数量与输出符合预期。功能失败时不发布有效优化分；记录哪一步、哪个输入失败。

第二关：可实现

综合、布局布线完成；满足声明的时序约束和必要检查范围。若平台不提供某项检查，标记缺失，不能声称完整检查通过。

第三关：收益与代价

同一条件下比较周期、时序、映射面积；有有效活动数据及分析流程时才报告功耗估计。缺失功耗用 unavailable，不能填 0。

原版也必须跑完整链路。相同程序、核心边界、工艺、库、工具、约束、种子与测量范围，才能比较。周期减少不自动等于更快；如果候选达不到目标频率，应标记时序失败，而不是只报告 IPC 提升。

首版分别列出各项指标，不把缺失项拼成一个漂亮总分。若后续需要训练奖励，应采用“正确性与必要实现检查先通过，再计算优化奖励”的规则，并在训练前冻结奖励定义。

当前：一次性评测模式

模型读任务并提交一次；不调用评测器获取修改反馈；冻结后关闭模型阶段。环境自动运行全链路，结果供用户与研究分析使用，不训练模型权重。

后续：训练模式

复用同一个执行器和裁判，另接训练器、任务采样与奖励接口。训练任务与独立测试任务隔离，按设计来源控制泄漏；这是独立协议，不暗中改变当前一次性规则。

05 · 从模块调通到一道完整任务

里程碑完成依据
A · 模块准备沿用 v0.2 模块计划：各工具用上游小样例证明能运行和识别错误。先核对 ARM64、工艺资料和资源需求。
B · 贯通原版设计统一 CPU、顶层、工艺与约束，原版从 RTL 测试跑到布局与最终检查；所有输出都能追溯到同一原版。不能继续用无关样例拼结果。
C · 验证控制器和裁判原版副本得到一致结果；已知逻辑错误、超时、缺产物、时序违规被正确识别；失败阶段阻断下游，不能错误报成功。
D · 接入一个模型候选基线准备完成后才调用你的 Codex CLI，一次提交、冻结、自动评测，得到第一份端到端对照报告；不要求候选必须有提升。
E · 扩展为任务集加入更多独立设计与既有负载，固定来源、难度、约束与评测协议；再研究训练数据与奖励。任务数量不能靠重复同一设计凑数。
当前实际状态：已有 ChampSim 预取器实验与 VM 基础；RTL、综合、物理实现等新增模块尚未按本方案验收。本次只完成全链路设计，不代表环境已经贯通。正式工艺签核、制造与实测不属于当前可交付范围。

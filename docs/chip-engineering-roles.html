01 · 原来的 7 步，需要怎样修正？

方向正确，层级过粗

架构 → 微架构 → RTL → 验证 → 综合 → 物理 → 签核，是数字设计的简图。它缺少 SoC 集成、DFT、跨时钟/低功耗、封装，以及流片后的工作。

一道工序，不等于一个人

这里把每个责任域写成一份 JD。小团队可以兼岗，大团队会继续拆岗；STA、物理验证、CAD 等也可能归属同一组织。不能把 28 张卡当作必需招聘 28 人。

验证、封装和软件，要并行开展

验证从规格制定开始，持续覆盖 RTL、集成和修改；DFT 早期规划；封装约束影响引脚与 floorplan；固件可在模型或原型上提前开发。

签核、流片和量产，必须分开

签核是各专业按约定标准确认结果；流片是批准并交付制造数据；之后还有制版、晶圆制造、封装、测试、回片验证和量产爬坡。

当前最准确的定位：我们已建立若干开源 EDA 模块的工程验收环境，尚未组成同一设计的端到端流程。小样例通过不等于掌握该岗位全部职责，更不等于工业签核或量产就绪。

02 · 实际协作流程

① 产品与架构系统架构 → 微架构与性能② 设计与集成RTL → SoC 集成；DFT 并行③ 实现与收敛综合 ↔ 物理 ↔ 时序/功耗/规则④ 批准流片多专业签核 → 受控交付⑤ 制造与封装制版 → 制造 → 晶圆测试 → 装配⑥ 回片与量产成测 / 实验室验证 → 资格认证与良率
贯穿全程：验证、形式化、CAD 与版本管理；问题可返回任何上游环节，不是单向流水线。
并行支线：模拟 IP 设计与定制版图、封装设计、固件与原型、制造测试开发。其交付物汇入顶层集成与量产。

这是常见职责划分，不是一套所有公司的固定组织图。具体测试顺序随封装形态和产品调整；晶圆厂与封测厂通常承担制造支线，设计公司不必自建工厂。

03 · 交接要交产物，不能只交一句“通过”

交接必须带走的东西放行责任
架构 → 设计 / 验证可追溯规格、接口、预算、异常行为、验收场景架构负责人牵头，设计/验证共同评审
RTL → 综合 / 后端冻结代码、SDC/电源意图、验证状态、DFT 计划、开放问题设计与验证负责人；综合/后端确认输入可用
综合 → 物理映射网表、约束、库版本、等价/一致性证据、阶段预算综合与物理负责人共同核对
物理 → 签核最终网表/版图、SPEF、角点模式、DRC/LVS/EMIR/时序等证据各专业分别签核；不是只看 GDS 文件存在
签核 → 晶圆厂冻结版本、校验和、交付表、批准例外、制造资料项目授权签核人批准，流片接口执行交付
样片 → 量产回片验证、ATE、可靠性、失效与良率报告产品/测试/质量和制造团队按产品门禁放行

覆盖率、良率、功耗、时序等阈值应按产品和工艺约定；不在这里伪造一个适用于所有芯片的百分比标准。

04 · 岗位 JD 卡片

每份卡片是本项目整理的通用职责模板，不是逐字复制的招聘广告。任职能力列出实际工作技能，不硬设学历、年限或薪资；按职级招聘时另补。参考链接用于核对岗位/流程类别，部分细分边界为工程归纳。

系统架构工程师 / SoC Architect

岗位目标
把产品需求变成可实现、可验证的芯片规格。
主要职责
定义功能、接口、性能/功耗/成本预算；选择工艺与 IP；协调软硬件取舍。
接收什么
产品场景、工作负载、成本和功耗限制
交付什么
芯片规格、系统框图、预算分配、验收场景
如何验收
规格可追溯且可测；关键风险和取舍经跨团队评审
任职能力
计算机体系结构、系统建模、接口协议、PPA 权衡

本项目现状　未覆盖；现有任务规格不等于产品架构设计

微架构与性能工程师 / Microarchitecture & Performance

岗位目标
决定流水线、Cache 和调度结构如何满足架构目标。
主要职责
构建性能模型；分析瓶颈；比较结构；编写微架构规范并与 RTL 对齐。
接收什么
架构规格、真实负载、技术预算
交付什么
微架构说明、模型、性能分析、RTL 接口约定
如何验收
同一负载与配置下可复现；性能与面积/功耗假设明确
任职能力
C/C++、CPU/存储层次、统计、RTL 阅读

本项目现状　局部覆盖：ChampSim 预取器短 trace 实验；未连接 RTL

数字 RTL 设计工程师 / RTL Design

把微架构写成可综合的硬件代码。

交付什么

任职能力

SoC 集成工程师 / SoC Integration

把多个 IP 接成能协同工作的系统。
主要职责

J05 · 验证岗位 / 流程参考 ↗

数字验证工程师 / Design Verification

岗位目标
在流片前尽可能找出功能错误。
主要职责
从规格制定验证计划；搭建参考模型、激励和 scoreboard；回归、覆盖率分析与问题定位。
接收什么
规格、RTL、接口协议
交付什么
验证环境、测试集、覆盖报告、缺陷记录
如何验收
需求与测试对应；覆盖缺口经审查；未解决缺陷有处置
任职能力
SystemVerilog/UVM、SVA、随机约束、调试与脚本

本项目现状　局部覆盖：原版固件和小测试；无完整 UVM/覆盖率收敛

形式化验证工程师 / Formal Verification

岗位目标
用性质证明或等价检查补足仿真的盲区。
主要职责
写断言与环境假设；分解证明；检查空洞成立；定位反例；做 RTL/网表等价验证。
接收什么
RTL/网表、性质、复位和合法输入假设
交付什么
证明报告、反例、未证明项与假设清单
如何验收
证明范围、界限和假设明确；超时不算通过；等价失败闭环
任职能力
SVA、形式化方法、状态空间、等价验证

本项目现状　局部覆盖：计数器归纳证明；CPU 综合后仿真不等于等价证明

CDC/RDC 与低功耗工程师

岗位目标
确保跨时钟、跨复位和电源切换时仍然可靠。
主要职责
检查同步器和握手；分析复位交互；维护 UPF 电源意图；验证隔离、保持和电源状态切换。
接收什么

交付什么
CDC/RDC 报告、低功耗检查、例外说明、修复方案
如何验收
跨域问题与例外审查完成；合法电源状态和切换行为正确
任职能力
亚稳态、异步协议、CDC/RDC、UPF、低功耗验证

本项目现状　未覆盖；单时钟小样例不能代表此能力

DFT 可测性设计工程师 / Design for Test

岗位目标
让制造后的芯片能被高效检测出缺陷。
主要职责

如何验收
按约定故障模型审查覆盖与未测项；测试模式功能/时序通过
任职能力
Scan、ATPG、MBIST、JTAG、故障模型

本项目现状　未覆盖；功能测试通过不能替代制造缺陷测试

J09 · 实现岗位 / 流程参考 ↗

综合工程师 / Logic Synthesis

岗位目标
把 RTL 转成目标工艺可实现的门级网表。
主要职责
维护 SDC 与库配置；综合和映射；分析面积、时序、功耗；与设计/DFT/后端迭代。
接收什么
RTL、标准单元库、时序约束、电源意图、DFT 要求
交付什么
映射网表、约束、PPA 报告、等价检查输入
如何验收
无未解析逻辑；约束有效；功能一致；满足阶段预算或记录差距
任职能力
综合、Liberty、SDC、Tcl、PPA 优化

本项目现状　局部覆盖：Yosys 通用综合和计数器 Nangate45 映射

05 · 对你的仿真任务平台意味着什么？

适合的基本单位是“一份工程交付任务”，不是整份 JD。例如“修复一个已定位的 RTL 错误”“在功能不变时降低面积”“处理一组时序违例”。同一岗位可以产生多类任务，每类都有独立输入和验收。

岗位 / 任务目标
输入版本 + 规格 + 允许修改范围
工具 / 工艺 / 模式 / 角点 / 资源预算
必须交付的设计文件与说明
隐藏验收：正确性 → 约束 → 性能/面积等指标
失败类别 + 原始证据 + 可复现命令

当前可优先连接：RTL → 功能验证 → 综合/映射 → 物理 → 时序/公开 DRC。仍需统一设计，并补齐阶段依赖、约束和一致性验证。

不能仅靠现有环境自动造出的标签：真实工艺可制造性、制造良率、硅片寿命、真实回片功耗、ATE 量产质量。它们需要相应模型、认证工艺包或真实硬件/制造数据。

你的模型评测约束保持不变：Codex 一次生成、冻结后统一评测、不回传结果让它继续改；不因 JD 拆分就自动启用多个模型角色或训练。

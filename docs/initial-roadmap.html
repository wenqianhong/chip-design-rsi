Personal builder playbook · 2026

Agent for Chip Design

给个人开发者的一张路线图：先看懂芯片设计在做什么，再用开源工具搭出能跑、能测、能比较 Agent 能力的 Demo。第一年不买商业 EDA 授权。

目标：研究 + 创业验证软件预算：尽量 $0先 Linux / DockerAgent：Codex 等 Coding Agent

01｜芯片设计到底在做什么？

从“想做什么芯片”到“做出能工作的芯片”

可以把芯片设计理解成：先定功能和性能目标，再设计内部结构，写成硬件代码，反复验证，最后把逻辑变成真实的晶体管布局。

01 · PLAN架构设计CPU / GPU / NPU 要做什么？性能、功耗、成本目标。
02 · DESIGN微架构设计流水线、Cache、调度器、计算阵列怎么组织。
03 · RTLRTL 实现用 Verilog / SystemVerilog 描述硬件电路。
04 · VERIFY验证与调试仿真、测试、形式化检查，找出设计错误。
05 · SYNTH逻辑综合把 RTL 转成标准单元组成的门级网表。
06 · PHYSICAL物理设计布局、时钟树、布线，优化面积和时序。
07 · SIGNOFF签核与流片时序、版图规则、电源完整性检查，准备制造。
别混为一谈：gem5 / ChampSim 这类工具是在模拟“芯片架构表现”；Verilator / Yosys / OpenROAD 则能逐步验证和实现“硬件电路”。架构模拟跑得快，但不等于已经做出了可流片芯片。

02｜每类任务用什么工具？

优先选开源、可脚本化、能自动评分的工具

CPU / GPU / NPU 架构与微架构

改算法或参数 → 跑 workload → 看性能变化
ChampSimgem5Ramulator 2Accel-Sim / GPGPU-SimSCALE-Sim

典型任务：Cache / Prefetcher、分支预测、CPU 参数、GPU 调度、NPU 数据流优化。

评估：IPC、MPKI、延迟、吞吐、带宽、能耗估算。

入门先用 ChampSim；gem5 更全面但更重。GPU 模拟器安装和校准成本较高，放第二阶段。

CPU / SoC RTL 设计

改真实硬件描述 → 编译、仿真、验证
VerilatorcocotbGTKWaveChiselChipyard / BOOM / Ibex

典型任务：生成或修改 Verilog、实现模块、修复 Bug、集成总线和 IP。

评估：测试通过率、功能覆盖率、仿真时间、资源消耗。

先用 Ibex 等较小设计做 Demo；BOOM / Chipyard 更适合后续做复杂 CPU。

功能验证 / 形式化验证

生成测试 → 找 Bug → 修复 → 回归
VerilatorcocotbYosysSymbiYosysGTKWave

典型任务：Testbench 生成、RTL Debug、断言检查、等价性验证。

评估：隐藏测试通过率、Bug 修复率、覆盖率、证明结果。

综合 / 物理设计 / PPA

RTL → 网表 → 布局布线 → 指标反馈
Yosys + ABCOpenROADOpenSTASKY130 / GF180 PDK

典型任务：综合参数优化、Floorplan、Placement、CTS、Routing、时序修复。

评估：面积、WNS / TNS、线长、拥塞、功耗估算、DRC。

OpenROAD Flow Scripts 可串起较完整的 RTL-to-GDS 流程；结果受 PDK、约束和设计规模影响。

模拟 / 混合信号电路

改电路参数 → SPICE 仿真 → 读性能指标
ngspiceXschemPython / SciPyMagic / Netgen

典型任务：运放、滤波器、振荡器等电路参数优化和鲁棒性分析。

评估：增益、带宽、相位裕度、功耗、噪声、PVT 表现。

系统级 / 软件工作负载验证

把芯片放进软件场景，看真实任务表现
gem5RISC-V toolchainLinux / benchmarksQEMU（功能执行）

典型任务：跑程序、分析瓶颈、比较配置、验证系统性能。

评估：运行时间、吞吐、启动成功率、性能回归。

03｜建议先搭的“零商业授权”工具栈

不要一次装完所有东西，先跑通两条闭环

优先级环境 / 工具先做出的 Demo为什么先做
P0ChampSim + C++ + PythonAgent 改 Prefetcher，在固定 trace 上优化 IPC / MPKI。任务边界清楚、运行快、结果易比较，适合第一个 Agent Benchmark。
P0Verilator + cocotb给一个带 Bug 的 RTL 模块，让 Agent 修复并通过隐藏测试。自动判分直接，容易做出可复现任务集。
P1Yosys + OpenROAD + OpenSTA + SKY130给定 RTL 和约束，跑综合及物理实现，比较 PPA。体现真正 EDA 流程，但运行资源、PDK 和流程调试更复杂。
P1gem5 + Ramulator 2修改 CPU / 内存配置，跑选定 workload 并比较性能。更接近系统级架构研究，适合第二批任务。
P2SCALE-Sim / Accel-Sim探索 NPU 数据流或 GPU 微架构参数。产业相关性强，但先确认依赖、模型和校准成本。
P2Xschem + ngspiceAgent 优化一个运放或滤波器电路指标。补充模拟电路方向，不必作为第一版主线。
零成本不等于零条件：开源软件通常可免费使用，但每个仓库、依赖、PDK、benchmark trace 和设计数据都有自己的许可证。商用前逐项审查；不要把受限的 SPEC、厂商 PDK 或商业工具数据打包分发。

04｜把工具变成 Agent 能用的环境

重点不是做一堆 MCP，而是做可复现的任务闭环

AgentCodex / 其他 Coding Agent
→
统一接口CLI / Python SDK / MCP
→
Environment任务、状态、运行、日志、预算
INPUT任务规格目标、约束、初始设计
ACTIONAgent 修改代码、参数、配置
RUN调用工具仿真 / 编译 / 综合
OBSERVE结构化反馈日志、指标、失败原因
EVAL独立评分隐藏测试、性能、成本

每个任务都要能 reset、run、inspect、evaluate。评估器要独立于 Agent，避免 Agent 自己报告“我成功了”。

05｜个人开发者的 90 天计划

先有能演示的闭环，再谈平台化

WEEK 1–2

跑通一个工具

选 ChampSim。编译、运行官方示例，确认结果稳定；建立一个 baseline 和结果解析脚本。

WEEK 3–6

做出 Agent Demo

让 Agent 修改 Prefetcher，自动运行实验、记录配置和指标；加入超时、资源限制、重复运行。

WEEK 7–12

做成可评测产品

加入 RTL Debug 环境、隐藏测试、统一任务格式和排行榜；比较不同 Agent 的成功率、成本和耗时。

06｜创业切入点：先卖“评测能力”，不是卖仿真器

第一阶段：开发者工具

开源任务集 + 本地 Runner + 结果报告。让芯片团队能测 Coding Agent 是否真的会改设计、跑仿真、提升指标。

第二阶段：团队评测平台

私有 RTL / workload 接入、隔离执行、许可证与算力调度、Agent 横向比较、回归追踪。

建议的首个产品定位：“面向芯片设计任务的 Agent Evaluation & Execution Platform”。先聚焦一个窄场景（例如 Prefetcher 优化或 RTL Bug 修复），把任务、运行和评分做扎实，再扩展到完整 EDA flow。
一句话路线：先用 ChampSim 做 CPU 微架构优化 Demo，再用 Verilator + cocotb 做 RTL 验证 Demo，最后接入 OpenROAD 做真实 PPA 流程。
商业软件（Cadence / Synopsys / Siemens）先不买；等有明确客户需求，再谈评估授权、合作许可和商业部署条款。

模块已经跑到哪一步？

先用固定样例证明工具能运行、结果能判对错。每张卡代表独立模块；它们目前还不是同一个 CPU 的全链路。

M2 · RTL 仿真

两种仿真器通过

PicoRV32 原版固件分别在 Icarus 和 Verilator 下通过。计数器也完成回绕、保持和复位检查。

M3 · 验证

能识别故意错误

语法错误会编译失败；把计数 +1 改成 +2 后，测试和形式化证明都识别出了错误。形式化范围是小计数器，不是整个 CPU。下载错误反例波形：使能后计数从 0 变为 2，违反每次 +1 的断言。

M4 · 综合

网表行为通过

Yosys 已生成 PicoRV32 和计数器网表；综合后的 PicoRV32 重新跑原版固件并通过。计数器另完成 Nangate45 标准单元映射，并通过相同测试；仿真单元模型由 Liberty 生成，不含真实延迟。

M5 · 物理实现

物理各阶段通过

OpenROAD 已编译并运行上游 GCD / Nangate45 样例。布局、时钟树、详细布线、填充和寄生提取均有产物；全部连线完成，路由 DRC 与天线违规为 0。ARM64 兼容补丁已保留。

M6 · 规则与时序

时序 / DRC 已运行

实际 GDS 经 FreePDK45 规则检查为 0 项违规；已知窄线错误能被识别。时序约束检查通过，过紧时钟能报出负裕量。Nangate45 平台包缺 LVS 规则，LVS 明确记为 unsupported。

首次准备环境：python3 scripts/modules.py setup（先确保仓库内的 Lima 已安装；会下载源码并编译 OpenROAD）。已配置环境中运行：python3 scripts/modules.py logic 或 python3 scripts/modules.py drc，标准单元映射用 python3 scripts/modules.py mapping；物理实现用 python3 scripts/modules.py physical，版图检查用 python3 scripts/modules.py layout。再执行 python3 scripts/modules.py collect 收集结果，使用 python3 scripts/modules.py stop 停止 VM。代表性日志：PicoRV32 门级仿真 / 标准单元映射 / 错误反例。完整日志和大型产物位于 .chipbench/modules/results/，不上传 VM 镜像和工具二进制。

这些结果证明工具模块可用，不代表 CPU 完整正确、真实工艺签核通过或已经可制造。计数器与线宽样例是工程验收，不作为模型能力 benchmark。
